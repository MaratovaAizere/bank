# Northstar Bank — три роли с серверными ограничениями

Обновление для папки `bank-frontend 4`. Не меняет PostgreSQL, данные, `.env` или `server/scoring.js`.

## Что добавлено

| Роль | Видит | Может изменять |
|---|---|---|
| Администратор | Все таблицы, кредитный скоринг, аналитика, реестр ролей | Все таблицы + контакты, обновление отчёта |
| Кредитный специалист | Клиентов, счета, владельцев, филиалы, кредиты, кредитные платежи, скоринг | Только таблицы `loans` и `loan_payments` |
| Аналитик | Сводная статистика и отчёт по филиалам (без клиентских персональных данных) | Ничего |

Ограничения проверяются **на сервере API**. Выбор названия роли в форме входа не даёт прав: API самостоятельно определяет роль по секретному ключу. Клик по роли в правом верхнем углу выполняет выход, после чего можно зайти с другим ключом.

Это демонстрационная модель с **отдельным общим ключом для каждой роли**, а не полноценная корпоративная аутентификация индивидуальных пользователей. Настоящие роли PostgreSQL отдельно отображаются в административной панели и не равны ролям сайта.

## Установка на Mac

1. Остановите оба процесса в VS Code через `Control + C` (`npm run server` и `npm run dev`).
2. Создайте резервную копию папки `bank-frontend 4` (через Finder: Duplicate).
3. В VS Code откройте терминал и перейдите в существующий проект:

   ```bash
   cd ~/Downloads/"bank-frontend 4"
   ```

4. Распакуйте обновление в корень существующего проекта:

   ```bash
   unzip -o ~/Downloads/Northstar_Bank_RBAC_Update.zip -d .
   ```

5. В **существующий локальный** `.env` добавьте **две строки** ниже. Не заменяйте свой `API_TOKEN` и `PGPASSWORD`:

   ```dotenv
   CREDIT_OFFICER_TOKEN=YOUR_OWN_RANDOM_SECRET_1
   ANALYST_TOKEN=YOUR_OWN_RANDOM_SECRET_2
   ```

   Сгенерируйте **два разных** ключа (запустите команду дважды, каждый раз скопируйте новый результат):

   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```

   Вставьте результаты вместо `YOUR_OWN_RANDOM_SECRET_1` и `YOUR_OWN_RANDOM_SECRET_2`. Каждый ключ должен иметь минимум 24 символа. `API_TOKEN` остаётся **ключом администратора**. Если ключи не добавлены, соответствующие роли не смогут войти.

6. В первом терминале:

   ```bash
   npm run server
   ```

7. Во втором терминале:

   ```bash
   npm run dev
   ```

8. Откройте http://localhost:5173, выберите роль и введите **её** ключ:
   - Администратор → значение `API_TOKEN` из `.env`
   - Кредитный специалист → `CREDIT_OFFICER_TOKEN`
   - Аналитик → `ANALYST_TOKEN`

9. Для смены роли нажмите на имя роли в правом верхнем углу, а затем войдите под другой ролью.

## Как проверить

- Войти как аналитик и попробовать открыть скрытый раздел скоринга: его нет в меню.
- Отправить запрос к скорингу с токеном аналитика: API вернёт HTTP **403**.
- Войти как кредитный специалист: доступны кредиты и платежи с кнопками изменения, но не сотрудники, переводы и реестр ролей.
- Войти как администратор: в разделе «Аналитика и доступ → Роли и доступ» видны **роли приложения** и отдельно **роли PostgreSQL**.

Проверка прав без подключения к базе:

```bash
node --test server/auth.test.js
```

> Важно: для реального банковского продакшена необходимы индивидуальные учётные записи, безопасные серверные сессии, аудит, MFA и отдельный PostgreSQL-пользователь с минимально необходимыми правами. Нельзя полагаться лишь на скрытие кнопок в React. Не загружайте `.env` в GitHub.

## Что изменится в файлах

- `server/index.js`, новый `server/auth.js` — проверка ролей и прав доступа.
- `src/main.jsx` — форма входа с выбором роли, подписи, меню, разные действия.
- `src/BankAnalyticsPage.jsx` — реестр прикладных ролей и ограничения аналитика.
- новый `src/RoleDashboard.jsx` — отдельные панели специалиста и аналитика.
- `src/style.css` — стили.
- `.env.example` — подсказки по конфигурации.
- новый `server/auth.test.js` — проверки прав.

Существующий `server/scoring.js` не изменяется: ваш нормализованный кредитный SCORE 0–1 сохраняется. На сайте значение отображается с одним знаком после запятой.
